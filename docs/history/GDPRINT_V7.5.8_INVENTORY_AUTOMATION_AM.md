# GDprint v7.5.8 — Պատվեր → Պահեստ ավտոմատացում

Այս տարբերակը կառուցված է `GDprint_ADMIN_v7.5.7_PARTNER_STATUS_FIX_FULL.zip` հիմքի վրա։

## Ինչ է ավելացել

1. Նոր `service_inventory_rules` աղյուսակ՝ ծառայությունը պահեստային նյութի հետ կապելու համար։
2. Նոր `order_inventory_allocations` աղյուսակ՝ պատվերի պլանավորված, պահուստավորված, դուրս գրված և խոտան նյութերի համար։
3. Լուսանկարների համար նախնական կանոններ՝ A3, A4, A5, A6։
4. Եթե համապատասխան ֆոտոթուղթ պահեստում չկա, migration-ը ստեղծում է 0 մնացորդով placeholder նյութ, որը Admin-ը պետք է լրացնի իրական մնացորդով։
5. Կայքից / Customer App-ից պատվերի `order_details` գրանցվելու պահին նյութը **պահուստավորվում է**։
6. `Digital Print` փուլ մտնելիս կամ օպերատորի `Սկսել` գործողության ժամանակ նյութը **իրականում դուրս է գրվում** պահեստից։
7. Չեղարկված պատվերի դեռ չօգտագործված պահուստը ազատվում է։
8. Digital Print-ի `Խոտան` կամ `Վերատպում` գործողության ժամանակ `waste` քանակը լրացուցիչ դուրս է գրվում համապատասխան նյութից։
9. Պահեստի էջում այժմ երևում են՝ Ֆիզիկական / Պահուստ / Հասանելի մնացորդները։
10. Ավելացել է `Ծառայություն → նյութ ավտոմատացում` բաժին, որտեղ Admin-ը կարող է նոր կանոններ ստեղծել և փոխել նյութերի կապերը։
11. Ավելացել է `Պատվերների նյութեր` բաժին՝ վերջին պահուստների/ելքերի/պակասների պատմությամբ։
12. Ձեռքով «Ելք» անելիս համակարգը չի թույլատրում օգտագործել այլ պատվերների արդեն պահուստավորված նյութը։
13. Պակասի և քիչ մնացորդի դեպքում Admin notification է ստեղծվում։

## Տեղադրում

Supabase SQL Editor-ում նախորդ migration-ներից հետո գործարկեք՝

`supabase/043_inventory_order_automation.sql`

Հետո ստուգեք՝

```sql
select public.gd_inventory_automation_health();
```

Սպասվող հիմնական արժեքները՝

- `rules_table: true`
- `allocations_table: true`
- `photo_rules: 4`
- `details_trigger: true`
- `order_state_trigger: true`

## Փորձարկման օրինակ — 10 հատ A6 լուսանկար

1. Admin → Պահեստում բացեք `Ֆոտոթուղթ A6`։
2. Մուտք արեք, օրինակ, `100 հատ`։
3. Կայքից գրանցեք `Լուսանկարների տպագրություն → A6 → 10 հատ` պատվեր։
4. Admin → Պահեստում պետք է երևա.
   - Ֆիզիկական՝ 100 հատ
   - Պահուստ՝ 10 հատ
   - Հասանելի՝ 90 հատ
5. Պատվերը տեղափոխեք `Digital Print` փուլ կամ Digital Print աշխատակցով սեղմեք `Սկսել`։
6. Արդյունքը պետք է դառնա.
   - Ֆիզիկական՝ 90 հատ
   - Պահուստ՝ 0
   - Հասանելի՝ 90 հատ
7. Շարժերի պատմության մեջ պետք է լինի `Ավտոմատ ելք · պատվեր ...`՝ −10 հատ։

## Խոտանի օրինակ

Եթե 10 լուսանկարից 2 հատ խոտան է, Digital Print աշխատակիցը `Խոտան` կամ `Վերատպում` գործողության ժամանակ `waste = 2` է գրում։ Պահեստից ևս 2 հատ ֆոտոթուղթ դուրս է գրվում, և allocation-ում `խոտան՝ 2` է երևում։

## Կարևոր

A3-ը պատրաստված է որպես կանոն/պահեստային նյութ, բայց կայքի ներկայիս լուսանկարների պատվերի ձևում A3 տարբերակը դեռ չկա և գին սահմանված չէ։ Մինչև A3 գնային կանոնը որոշելը կայքի ընտրացանկին այն չի ավելացվել։

Այս կառուցվածքը ընդհանուր է և նույն Admin էջից հնարավոր է ստեղծել կանոններ նաև՝ բաժակների, Roll-up-ի, X-banner-ի, Kinder box-ի, լայնաֆորմատի, վինիլի և այլ ծառայությունների համար։
